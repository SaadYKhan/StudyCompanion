# Study Companion

Private, invite-only study site for two students in Dubai: MK, a Year 12 Edexcel International A Level student (Maths, Physics, Chemistry; SAT; US astrophysics applications) and ZK, a Year 7 student building strong maths and an early path to US universities.

- `site/` is the website (no build step). Cloudflare Workers serves it as static assets, plus a small API in `worker/index.js` for `/api/*` (`wrangler.jsonc`), from the `studycompanion` Worker (https://studycompanion.royalgroup.workers.dev). Once the Worker is connected to this repo (Worker → Settings → Build → Git repository; deploy command `npx wrangler deploy`), every push to `main` redeploys. The `name` in `wrangler.jsonc` must match the Worker's name.
- Sign-in is Cloudflare Access on the whole Worker (emailed one-time code, 7-day sessions). Who may sign in: Zero Trust → Access → Applications → "studycompanion - Cloudflare Workers" → policy "Family". The API re-checks the Access token (`ACCESS_AUD`, `ACCESS_TEAM` in `wrangler.jsonc`) on every call.
- Accounts and data live in the D1 database `studycompanion-db` (schema: `db/schema.sql`). Built for many families: families → students; users (by sign-in email) see a child only through `memberships` (parent = every child in the family; student/tutor = one child). Every change is written to `audit_log`. Email addresses are kept only in the database and Access, never in this repo.
- `GET /api/me` returns the signed-in person and the children they can see. `POST /api/import-legacy` (parents only) copies the question log from `worker/legacy.json` into the database, safely re-runnable. After editing `site/data/questions.js`, run `node tools/export_legacy.mjs` to refresh `worker/legacy.json`.
- `tools/test_api.mjs` runs the Worker locally with a throwaway signing key and checks sign-in, permissions and the import (`WRANGLER=path/to/wrangler node tools/test_api.mjs`).
- All dates, plans, syllabus topics and links live in `site/data/study.js`. To update the site, edit that file and push. Dates are `YYYY-MM-DD`, or `YYYY-MM` when only the month is known; `st: "expected"` marks a date that is not yet published.
- Every marked question for both students lives in `site/data/questions.js` (the Question log tab; each paper has `who`: "a" for MK, "b" for ZK). To add a newly marked paper, add it under `papers` and append its questions; each needs a paper, question number, topic, marks and the tutor's notes.
- Self-test cards for the Key notes tab live in `site/data/cards.js` (one object per card: unit, topic, type, question, answer, and for cards from a marked paper the source question). Never renumber a card's `id`: each student's progress is saved against it. When a new paper is marked, add a `mine` card for each new kind of mistake.
- Students' progress (topic ratings, scores, study log, roadmap ticks, redone questions, questions they add themselves) is saved in their own browser. The Study log tab has backup and restore.
- `tools/check_site.py` opens the site in a browser on three different dates, visits every tab and fills in every form; run it before pushing (`python3 tools/check_site.py`). Add `?today=YYYY-MM-DD` to the address to preview the site as of another date.
